VS Code with GitHub Copilot

VS Code uses its own key name and a typed entry, plus an inputs array that prompts for secrets instead of storing them.

What it does well

  • The inputs array prompts for a secret at first run and keeps it out of the committed file.
  • Each server declares its transport with an explicit type field.
  • Servers can be started, stopped and inspected from the editor without restarting it.

What catches people out

  • The top level key is servers, not mcpServers. Configuration copied from another client will not load.
  • Agent mode must be enabled for tools to be offered to the model.

A working example

This is the real block for AIOProductOS MCP, generated from its registry record. Every connector profile produces the same thing for whichever client you are using.

.vscode/mcp.json
{
  "inputs": [
    {
      "id": "productos-token",
      "type": "promptString",
      "description": "AIOProductOS personal access token (Settings → Tokens & Agents).",
      "password": true
    }
  ],
  "servers": {
    "mcp": {
      "type": "stdio",
      "command": "npx",
      "args": [
        "-y",
        "@aioproductoscom/mcp@0.18.0"
      ],
      "env": {
        "PRODUCTOS_TOKEN": "${input:productos-token}"
      }
    }
  }
}

Setting up a server

  1. Create .vscode/mcp.json in the workspace root.
  2. Paste the block below. Inputs marked as password are requested once and stored by the editor.
  3. Open the Chat view, switch to agent mode and confirm the server appears in the tools picker.
