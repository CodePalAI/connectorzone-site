Connect Dd to Zed

Hosted at dd.cz-agents.dev over streamable HTTP, also runs locally from the npm package. No credential is declared, and it reaches all 9 clients tracked here. This page covers the Zed dialect specifically, because a block copied from another client will not load here.

Where the configuration lives

All platforms
~/.config/zed/settings.json
Project scope
.zed/settings.json
Top level key
context_servers

The block to paste

settings.json
{
  "context_servers": {
    "dd": {
      "source": "custom",
      "command": "npx",
      "args": [
        "-y",
        "@czagents/dd@0.3.7"
      ]
    }
  }
}
  • Zed calls these context servers and the source field is required.
  • Merge this into ~/.config/zed/settings.json rather than replacing the file, so servers you already run keep working.

Steps

  1. Open the Zed settings file with the command palette entry zed: open settings.
  2. Merge the context_servers block below into the top level object.
  3. Open the agent panel and confirm the server is listed as running.

What to watch for in Zed

  • The key is context_servers and each entry needs a source field, so other clients configuration does not transfer.
  • Local processes only. A remote HTTPS server needs a local bridge process in front of it.

Behaviour above was read from Zed documentation, Model Context Protocol on 2026-07-30.

Before you connect it

Published under the verified namespace dev.cz-agents, which resolves to the same domain as the linked website. That pairing is the strongest ownership signal the registry exposes.

No credential is declared in the registry record. A hosted endpoint may still apply its own rate limits or sign in step.

A listing in the official registry is a namespace ownership check, not a security review. ConnectorZone does not execute connectors and does not audit their code. Treat every connector as third party software with the access you grant it.
