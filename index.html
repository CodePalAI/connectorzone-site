    About this project

    What is a Model Context Protocol connector?

    An MCP connector, usually called an MCP server, is a small program or hosted endpoint that exposes tools, resources and prompts to an AI client over the Model Context Protocol. The client starts or calls it, then the model can use whatever it exposes. ConnectorZone catalogs 14,240 of them.

    Why does the same connector need different configuration per client?

    The protocol standardised how a client talks to a server. It did not standardise how you declare that the server exists. Claude Desktop reads mcpServers, VS Code reads servers, Zed reads context_servers, Codex CLI reads TOML, and Gemini CLI and Windsurf disagree on the field name for a hosted endpoint. A block copied between two clients parses cleanly, configures nothing and reports no error.

    Where does the data come from?

    Every profile is derived from the official MCP Registry, read in full on 2 August 2026 and committed as a snapshot so each build is reproducible. Client behaviour comes from each vendor's own documentation, with the date it was read recorded on the client page.

    Are these connectors reviewed for security?

    No. A registry listing is a namespace ownership check, not a security review. ConnectorZone does not execute connectors and does not audit their code, so no page here carries a rating, a review or a tested install badge. Treat every connector as third party software with the access you grant it.

    Is ConnectorZone free, and can I use the data?

    Yes. The site is free, carries no advertising and loads no third party script. The catalog is published as static JSON at /api/, with no key and no rate limit, under CC0 1.0.
