About

A free catalog of MCP connectors that writes the configuration each client actually expects.

The problem

The Model Context Protocol standardised how an assistant talks to a tool. It did not standardise how you tell your assistant that the tool exists. Nine widely used clients read server definitions from nine different places, in four different shapes, using at least three different field names for the same hosted endpoint.

The result is that a working configuration for one client is a broken configuration for another, and the failure is silent. Nothing errors. The server simply never appears.

What this site does

ConnectorZone reads every record in the official registry, normalises it into one model, and generates the exact configuration block each client expects from that record. Alongside it, each profile publishes a compatibility verdict with the rule behind it, a provenance reading, a completeness score with its full breakdown, and links to everything the claim rests on.

14,240 connectors have profiles. 420 have per client install guides. The rest of the registry is accounted for on the data status page, with the reason each record was held back.

What it refuses to do

  • No ratings or review scores, because there is no review process behind them.
  • No security assessments, because we do not audit code.
  • No claim that an install was tested, because none were.
  • No generated pages for arbitrary connector pairs or keyword combinations.
  • No third party analytics, advertising or tracking scripts of any kind.

How it is funded

It is not. There is no advertising, no paid placement, no sponsored listing and no affiliate link anywhere on this site. Ranking is a published formula applied identically to every record, and no publisher can change their position by paying.

If that changes, it will be disclosed on this page before it ships, and any paid placement will be labelled on the page it appears on.

How it is built

A static site generated from a committed snapshot of the registry. No server runtime, no database, no client side framework. The search index is fetched on demand and the rest of the JavaScript on a page amounts to a copy button.

The source is on GitHub, including the sync pipeline, the scoring rules and the client dialect definitions. If you disagree with a rule, you can read it.

Corrections and contact

Wrong pages get fixed or removed. Use the report page to tell us what is wrong, and the submit page if you publish a connector that is not represented properly here.
