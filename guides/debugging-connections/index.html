Debugging a connector that will not load

An ordered checklist for the silent failures, from invalid JSON to tool budgets, with the command that answers each one.

7 minute read. Updated 2026-07-30.

MCP failures are quiet. A server that cannot start usually does not announce itself, it just never appears. Work through this list in order and you will find almost all of them inside five minutes.

1. Is the file valid?

A single trailing comma invalidates a whole JSON file, and most clients respond by ignoring every server in it rather than the one you broke. If several servers disappeared at once, this is almost certainly why.

Run the file through any JSON validator, or open it in an editor that reports syntax errors. For Codex CLI the file is TOML, so a JSON snippet pasted in will fail differently and more loudly.

2. Is the top level key right for this client?

VS Code reads servers. Zed reads context_servers. Codex CLI reads [mcp_servers.name] tables. Everything else in our reference reads mcpServers.

A block copied from a different client parses as valid JSON and configures nothing. This is the second most common cause after syntax errors, and it produces exactly the same symptom: the server is simply absent.

3. Does the command run by hand?

Copy the command and arguments out of the config and run them in a terminal.

npx -y some-mcp-package

If that fails in your shell it will fail in the client, and the terminal will tell you why: package not found, wrong Node version, missing Python, no Docker daemon, network blocked. The client will tell you none of that.

Two frequent findings. First, the runtime is missing entirely: uvx requires uv installed, container images require a running Docker daemon. Second, the client does not have the same PATH as your interactive shell, which is common for desktop applications launched from a dock. If the command works in a terminal but not in the client, try an absolute path to the executable.

4. Did the client actually reload?

Claude Desktop needs a full quit and relaunch on macOS. Closing the window leaves the application running and the old config in memory. Use the quit command or the keyboard shortcut, then reopen.

Editors usually offer a restart action for a single server, which is much faster than restarting the editor.

5. Is the remote field name correct?

For hosted endpoints, the field name is client specific:

  • url for Cursor, Claude Code and Claude Desktop
  • httpUrl for streamable HTTP in Gemini CLI, url for server sent events
  • serverUrl for Windsurf
  • url with "type": "http" for VS Code

The wrong field does not error. It configures a server with no address, which appears as a server with no tools.

6. Zero tools usually means no credential

If the server appears and reports zero tools, it started and returned an empty tool list. That almost always means a missing or rejected credential.

Check the environment block against the variables the connector profile lists. Check that the placeholder was replaced. Check that the key is valid by calling the upstream API with it directly, using curl, before you blame the connector.

7. Tools vanished after adding another server

Several clients cap the total number of tools offered to the model. Crossing the cap drops tools silently, and which ones survive is not always the ones you want.

Disable the largest connector and see whether the missing tools return. If they do, you found it. Focused connectors are worth more than comprehensive ones for exactly this reason.

8. It worked last week

Two likely causes.

An unpinned package resolved to a new version. If the config has no version, your package manager fetches whatever is current at startup. Pin it and the problem stops moving.

A protocol revision moved on one side. Update both the client and the server package before investigating further. See the protocol guide for what to check.

9. Container specific problems

A container image needs -i to keep standard input open, which our generated config always includes. Without it the process starts and immediately loses the channel.

Volume mounts are the other frequent issue. A container cannot see your files unless you mount them, so a connector that reads local paths needs an explicit mount and an absolute path inside the container rather than on the host.

10. Still stuck

Open the connector profile page on this site, follow the repository link and read the issue tracker. Someone has usually had the same problem, and a connector whose tracker has no answers is telling you something useful about maintenance.

If the problem is with what this site published, rather than with the connector, tell us on the report page.
