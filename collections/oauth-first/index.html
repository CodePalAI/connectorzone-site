Connectors that use an authorisation flow

A pasted API key lives in a file, gets committed by accident and rarely gets rotated. An authorisation flow moves the grant into a consent screen you can read and a session you can revoke. When both options exist for the same service, the flow is almost always the better choice.

Selection ruleThe registry record references an authorisation flow rather than a static key.

Before you attach any of these

  • Read the consent screen. The scopes requested are the actual permission you are granting, not the ones described on a marketing page.
  • Confirm where the refresh token is stored by your client, because that file becomes as sensitive as a password.
  • Revocation should be one action in the upstream service. If it is not, treat the connector as a long lived key.

Membership is recalculated from the registry snapshot on every build, so a connector can enter or leave this set when its record changes. Read thesecurity guide before granting access to anything sensitive.
